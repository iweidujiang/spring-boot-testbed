实验管理

验证实验的创建、状态流转及非法操作拦截

用例 1：创建实验
验证 POST /api/experiments 能成功创建实验并返回正确结构
操作步骤
  1. 发送 POST 请求到 /api/experiments
  2. 请求体：{"experimentKey":"test-create","description":"创建测试"}
预期结果
HTTP 状态码：201 Created
返回 JSON 包含 experimentKey = "test-create"
返回 JSON 包含 status = "DRAFT"
用例 2：查询实验列表
验证 GET /api/experiments 返回所有实验
操作步骤
  1. 发送 GET 请求到 /api/experiments
预期结果
HTTP 状态码：200 OK
返回 JSON 数组，长度 ≥ 1（含预置 demo-exp）
每个元素包含 id、experimentKey、status
用例 3：状态流转（DRAFT → ACTIVE → PAUSED → ARCHIVED）
验证实验状态按正确顺序流转
操作步骤
  1. 创建实验 test-flow（初始 DRAFT）
  2. PATCH /api/experiments/test-flow/status → ACTIVE
  3. PATCH → PAUSED
  4. PATCH → ARCHIVED
预期结果
每步返回 200 OK
最终 status = "ARCHIVED"
流转路径：DRAFT → ACTIVE → PAUSED → ARCHIVED
用例 4：非法状态流转被拒绝
验证 ARCHIVED → ACTIVE 等非法操作返回错误
操作步骤
  1. 创建实验 test-illegal 并流转到 ARCHIVED
  2. PATCH /api/experiments/test-illegal/status → ACTIVE
预期结果
HTTP 状态码：400 Bad Request
返回 JSON 包含 message 字段，描述非法流转原因
用例 5：重复实验标识被拒绝
验证 experimentKey 唯一性约束
操作步骤
  1. 创建实验 test-dup
  2. 再次创建实验 test-dup（相同 key）
预期结果
第一次：HTTP 201 Created
第二次：HTTP 400 Bad Request
返回 message 提示重复
